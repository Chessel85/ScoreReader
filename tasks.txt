HOW TO USE THIS FILE
  - One line per task. Mark progress by changing [ ] to [x], or [~] for
    in progress. Add notes under a task with a "  > " prefix.
  - "Ref N" points at the numbered functional requirements table in the
    Product Definition Document; "NFR-N" at the non-functional table.
    Go and read the acceptance criteria there before starting a task.
  - Near-term phases (A-C) carry detail. Later phases are deliberately one
    line each - their detail depends on decisions not yet made. Expand them
    when we get there.
  - This file is tracked in git (since 2026-08-05) so it is backed up.
    Commit it along with the code changes each task produces.

PHASE ORDER RATIONALE
  Phase A comes first because four defects in the timeline model gate large
  parts of the spec: notes are not attributed to their real part (blocks
  Ref 7), rests are discarded (blocks Refs 14 and 16), and divisions and
  time signature are read once from the first match (breaks Ref 18 on any
  score that changes either mid-piece). Building playback or filtering on
  top of these means reworking that code later.

  A2 lands before A3-A5 on purpose. Those three all rewrite
  _build_timeline_from_xml, and Refs 17 and 18 are correct today. The
  characterisation tests are what prove they are still correct afterwards.

          Keeps the runtime list clean for the NFR-02 installer work later.
          Do NOT list mido - nothing imports it since the FluidSynth switch.
        > LAYOUT - mirrors the package tree, one test module per source module
              tests/conftest.py
              tests/fixtures/                     see A1 fixture decision D-6
              tests/models/test_music_data.py
              tests/parsers/test_musicxml_reader.py
              tests/widgets/test_region2_manager.py
              tests/audio/test_synth_engine.py
        > SPEED - this one matters
          MusicData(file_path=...) builds the timeline with ElementTree alone:
          ~1 ms. MusicXMLReader.load() also runs music21: ~460 ms. That is a
          460x difference. Timeline tests must construct MusicData directly;
          only the reader tests should pay for music21.
        > NO AUDIO IN TESTS
          MainWindow.__init__ (main_window.py:32) constructs SynthEngine(),
          which starts a WASAPI device. Tests must not open audio hardware -
          slow, noisy, and fails on machines without the DLLs. See D-7.
        > HEADLESS QT
          Set QT_QPA_PLATFORM=offscreen for the test session in pytest.ini so
          no window ever appears. pytest-qt supplies the qapp/qtbot fixtures.
        > CONFTEST FIXTURES to provide
          score_bourree / score_duet  paths to the two sample scores
          timeline(path)              MusicData built without music21
          null_synth                  SynthEngine stand-in recording calls
        > RUN
          .venv\Scripts\python.exe -m pytest
          single: ... -m pytest tests/models/test_music_data.py::test_pickup
          coverage: ... -m pytest --cov=models --cov=parsers --cov=widgets
        > DONE WHEN
          pytest runs green from a clean checkout, no window opens, no audio
          device is touched, and the run takes under ~5 seconds.

[ ] A3  FIX pickup numbering when the file already numbers the pickup 0
        - Ref 17, currently broken

          "subtract one from every measure" is right. Chessel Duet exports it
          as number="0" implicit="yes", so subtracting again gives measure -1,

          end-of-bar beat positions (beats 4,5,6 instead of 1,2,3).
        > Only re-index when the pickup is not already numbered 0.
        > Test both conventions: pickup must be measure 0 and the first full
          bar must be measure 1 in each.

        > Region2HierarchyModel.get_active_voice_tuples() returns

[ ] A5  Explicit rests become timeline events - Ref 16 AC2

[ ] A6  Track divisions and time signature as they change through the score

OPEN DESIGN DECISIONS
Mirrors the Discussion Points table in the Product Definition Document.
Add to this as decisions come up; move the outcome into the spec once settled.
###

D-1  Rests in one voice alongside sounding notes in another
     Decided 2026-08-04: an explicit rest in the score is an event with a
     step of "rest" and shows as "rest" in the Note region.
     Still open: when voice 1 sounds and voice 2 rests at the same position,
     should the rest appear in Region 3 next to the notes, or only when its
     voice is soloed via Region 2? Revisit during B2.

D-2  Global navigation keystrokes vs per-widget handling
     Already flagged in the spec's own Discussion Points. Navigation should
     work from anywhere in the main application area, but Qt widgets consume
     arrow keys natively. Options: an application-level event filter, or
     QShortcut with WindowShortcut context. Decide in C1.

D-3  Mechanism for forcing screen reader announcements from PySide6
     Needed for Ref 1 AC4, Ref 3 AC3 and Ref 5. Candidates: QAccessible
     alert events, live-region style updates, or driving the screen reader
     API directly. Decide in D1.

D-4  macOS speech recognition API
     Listed as TBC in the spec. Windows path is SAPI 5.4 /
     Windows.Media.SpeechRecognition. Decide in L3.

D-5  Multi-part GM programs and MIDI channel allocation
     Confirmed on Chessel Duet: the guitar part plays as piano because
     get_current_gmidi_program() (music_data.py:292) always returns
     parts_info[0]. Open: allocate one MIDI channel per part, or per
     (part, staff)? Channel 10 is percussion and must be skipped. 16
     channels is the hard ceiling. Decide in A8.

D-6  UK vs US music vocabulary
     From the spec's Discussion Points: bar/measure, crotchet/quarter note,
     quaver/eighth note. Open: which is the default, does the toggle affect
     screen reader announcements as well as on-screen labels, and does it
     reach Region 4 attribute names ("measure" is currently a literal key).
     Interacts with A9's tempo wording. Decide in F4.

D-7  How tests avoid opening audio hardware
     DECIDED 2026-08-05: constructor injection. MainWindow(synth=None)
     defaults to a real SynthEngine but accepts a stand-in, so tests can
     assert which notes, channel and program would have played - needed by
     Refs 8, 9, 13 and 14. Also makes the engine swappable for the macOS
     driver work in NFR-01.

D-8  Where test sample scores live
     DECIDED 2026-08-05: both. files/ is now tracked in git (66 KB) so the
     real MuseScore exports are backed up and usable as integration
     fixtures, plus hand-written minimal MusicXML under tests/fixtures/ for
     unit tests that need to isolate one behaviour.
