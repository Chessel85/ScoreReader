RECALL SCORE - MENU AND KEYBOARD SHORTCUT REVIEW
==================================================
Originally generated 2026-08-26 from the codebase as it stood at the time
(widgets/menu_builder.py, main_window.py, the five region widgets, and
docs/user_guide.md sections 14-15). Revised twice the same day after two
rounds of decisions - most Part 3 suggestions were accepted and have now
been IMPLEMENTED in the code and in docs/user_guide.md; a handful were
overridden by explicit user decisions instead, and a second round (after
the user actually navigated the menus with NVDA) found and fixed a real
accessibility bug plus several more mnemonic/shortcut adjustments. Part 1
and Part 2 describe the resulting, CURRENT state of the app. Part 3 is a
decision log, in two dated rounds, rather than a list of open suggestions.

PART 3: DECISION LOG
====================================================================
This section originally listed suggestions; each item below now records
what was actually decided and, where code changed, what was done.

3.1 Mnemonic (Alt+letter) collisions - ACCEPTED, FIXED
--------------------------------------------------------------------
All six collisions identified in the original review were fixed by
moving the ampersand to a different, still-sensible letter in each
item's own text (no shortcut keys were touched - only which letter is
underlined for Alt-based menu access):

  - Tools > Tuner: "&Tuner..." (T, collided with the parent &Tools menu)
    -> "T&uner..." (U).
  - Navigation > Find Next: "Find &Next" (N, collided with the parent
    &Navigation menu) -> "Find N&ext" (E). ("Find Ne&xt" - X - was tried
    first and rejected: X is already Move to Parts List's mnemonic in
    this same menu, which would have just traded one collision for
    another.)
  - Playback > Play/Stop: "&Play/Stop" (P, collided with the parent
    &Playback menu) -> "Play/St&op" (O).
  - Playback > Mixer: "&Mixer..." (M, collided with &Mute in the same
    menu) -> "Mi&xer..." (X).
  - Options > Terminology Language: "&Terminology Language" (T,
    collided with &Tempo Offset in the same menu) -> renamed AND
    re-mnemonic'd to "&Language (UK/US)" (L) - see 3.2 for the naming
    half of this change.
  - Options > Toggle Live MIDI Input: "Toggle Live &MIDI Input" (M,
    collided with Toggle &Metronome in the same menu) -> "Toggle Live
    MIDI &Input" (I).
  - Options > Voice Control Settings: had already drifted through two
    different collisions historically (first with &Edit's own mnemonic,
    then, after an earlier fix, with Live MIDI Input &Settings' own "S"
    in the same menu) -> "&Voice Control Settings..." (V), the first
    letter of the item's own most distinctive word rather than another
    guess at "Settings".
  - Options > Language (UK/US) submenu: "&UK" / "&US" both started with
    "U" - a pre-existing collision inside that two-item submenu, not one
    of the six top-level-menu collisions the original review looked at,
    caught only while double-checking every rename above. Fixed to
    "&UK" / "U&S".

Verified: every menu's (and submenu's) mnemonics are now unique within
their own menu AND distinct from that menu's own top-level letter (Part
1 lists the final result). A new regression test,
test_no_menu_mnemonic_collisions in tests/test_main_window.py, walks
every menu and one level into any submenu checking both collision
classes generically, so a future menu item that reintroduces either one
fails a test run instead of waiting for another live NVDA report.


3.2 Menu layout and naming
--------------------------------------------------------------------
  - Performance Report: user decision - moved to TOOLS, not the
    tentative "Score/Report" menu idea floated in the original review.
    Now sits with the Tuner as the app's two standalone, non-editing
    utilities.
  - Open Local Folder / Clear Preferences: user decision - moved to
    FILE, not merely reordered within Edit as originally suggested.
    File now ends with these two housekeeping items before Exit; Edit
    holds only Select All, Find, Instruments and Key Signature.
  - Mute/Solo/Unmute All/Unsolo All: user decision - KEEP in Playback,
    unchanged. Confirmed (see 3.3) that these are already restricted to

  - "Terminology Language" submenu: renamed to "Language (UK/US)" -
    both resolves its mnemonic collision (3.1) and applies the original

3.3 Keystroke logic
--------------------------------------------------------------------
  - Bare letters Z/X/C/V/B (region jumps) and F/S/D (tempo): user
    decision - KEEP UNCHANGED. The usability gain (easy to find by feel,
    already shipped and working well) outweighs the theoretical future
    risk flagged in the original review (a bare letter shortcut could
    swallow a keystroke meant for a text field, if one is ever added
    directly to the main window). Still worth remembering as a
    constraint on future main-window design, but not acted on now.
  - F/S/D global scope: user asked to "ensure" these work from any
    region and the status bar. Traced through the code
    (main_window.setup_shortcuts' window_shortcut() helper, which sets
    an explicit Qt.ShortcutContext.WindowShortcut) and confirmed this
    was already true - the same mechanism the already-working Z/X/C/V/B
    shortcuts use. No code change was needed; a new parametrized test
    (test_f_s_d_shortcuts_fire_from_any_region_or_the_status_bar in
    tests/test_main_window.py) now proves it for all five regions AND
    the status bar, closing the one combination (status bar) that had
    no prior test coverage.
  - Preview's Enter keystroke: user decision - NO CHANGE, including no
    wording/status-tip tweak. Left exactly as it was.
  - Alt+Right/Alt+Left (Find Next/Previous): user decision - NO CHANGE
    to the keystroke itself (only Find Next's menu mnemonic moved, per
    3.1 - the real shortcut is untouched).
  - F6/Shift+F6: confirmed already global and working correctly - no
    change.
  - F8/F9 (and Alt+F8/Alt+F9): user asked to confirm these only work
    with the Parts List region focused. Traced through
    controllers/focus_controller.py's update_region2_actions_enabled,
    which already disables all four QActions (and therefore their
    shortcuts, since a disabled QAction's shortcut does not fire)
    whenever focus is anywhere other than Region 2. This was already
    implemented before this review; no code change was needed, only
    confirmation - now made explicit in Part 2 above and in
    docs/user_guide.md.
  - Ctrl+A (Select All): user decision - this is DELIBERATE (it's what
    makes Shift+Space's "play every note together" meaningful) and
    should be (a) documented in the user guide and (b) added to the
    Edit menu, enabled only in the Note region. Both done: Edit >
    Select All is a new QAction (widgets/menu_builder.py), gated via
    FocusController.update_navigation_actions_enabled exactly like
    Home/End/Move to First/Last Note, replacing the old bare,
    undocumented QShortcut. docs/user_guide.md sections 5.5, 14.2 and
    15 all now describe it. Two new tests cover both the gating and the
    actual reselect behaviour.
  - Alt+PageUp/PageDown (Preview length): user asked for a spoken
    announcement of the new value ("Preview X bars"/"Preview X
    measures", per terminology setting). Added via
    RegionPresenter.announce_preview_length, the same one-shot
    QAccessibleAnnouncementEvent mechanism already used for the bar-
    number and quick-attribute-lookup announcements, called from
    main_window.increase_preview_bars/decrease_preview_bars. Covered by
    a new test.


3.4 Modifier protocol
--------------------------------------------------------------------
The general protocol proposed in the original review (Ctrl+letter for a
global toggle or long-established action, Ctrl+Shift+letter reserved
for opening a dialog, F-keys for state toggles on the focused region,
Alt+F-key for the "all/every" variant, Alt+arrow/PageUp/PageDown for
stepping through or adjusting the result of an action just performed,
Shift+key for the "fuller/together" variant, and bare letters reserved
for a short, deliberate exception list) was not disputed and stands as
the app's working convention going forward.

The one concrete outlier it flagged - Voice Control's toggle using
Ctrl+Shift+Enter, a dialog-shortcut-shaped combination, for what is
actually a toggle like Metronome/Position Announcer/Live MIDI Input -
has been fixed: user decision, changed to Ctrl+Enter (and Ctrl+Return
for the main keyboard key, mirroring the old dual-shortcut handling for
the numpad-vs-main-keyboard Enter distinction). This brings Voice
Control's toggle in line with the single-Ctrl+<key> family its three
siblings already use, while staying clearly distinct from every dialog's
Ctrl+Shift+<letter> shortcut and from every other single-Ctrl+<letter>
binding. No existing shortcut used Ctrl+Enter or Ctrl+Return before this
change (checked across the whole codebase), so no collision was
introduced.


3.5 Second round - findings from actually navigating with NVDA
--------------------------------------------------------------------
The first round was a read-through of the code; this round came from the
user actually arrowing through the menus with NVDA running, which
surfaced one real bug the code-only review couldn't have found, plus a
cluster of "this hint is wrong/unwanted" reports.

REAL BUG FOUND: arrowing down from Go to Measure... to Find... in the
Navigation menu announced NOTHING on that step, requiring an extra arrow
press to reach Find Next. Root cause: Find...'s QAction was the SAME
object added to BOTH the Edit and Navigation menus (a deliberate design
from the first round, meant to make Find reachable from either menu
without a duplicate/ambiguous Ctrl+F binding). Qt's accessibility bridge
does not reliably expose one QAction's accessible name across two
separate QMenu parents - the copy built second (Navigation, since Edit
is built first in MenuBuilder.build()) came through with no announced
name at all. Fixed by giving Find... exactly one home: it now lives ONLY
in Navigation, immediately before Find Next/Find Previous - which also
directly answers the user's separate observation that splitting Find
across two menus "is weird". Edit now holds only Select All, Instruments
and Key Signature. No test previously existed for a QAction shared
across two menus specifically because sharing one was the "clever" part
of the original design; the replacement design needs no such test, since
a QAction now only ever belongs to one menu, structurally.

Pause/Resume -> Pause: user decision. Ctrl+Space only ever pauses -
resuming is Space, the SAME key Play/Stop already uses - so "Resume" in
this item's own name was actively misleading about what pressing this
specific shortcut does. Playback > Pause now, text only, no shortcut
change.

Enter/Return made a real global shortcut: user decision - "Enter should
do the preview from anywhere - any region or the status bar. And enter
again should stop it from these areas." Previously Preview's "Enter" in
the Playback menu was DISPLAY TEXT ONLY (Qt's "\tEnter" tab-hint trick),
with no actual QShortcut behind it at all, specifically to avoid
colliding with the Note region's own Enter handling (jump to a typed bar
number, or preview if none pending). Now a real QAction shortcut
(Key_Enter/Key_Return, same numpad-vs-main-keyboard dual binding Voice
Control's Ctrl+Enter uses), but ENABLED ONLY OUTSIDE the Note region
(controllers/focus_controller.py's new update_preview_action_enabled) -
the inverse of Ctrl+A's Note-region-only gating. This is necessary, not
just tidy: a QAction's WindowShortcut is dispatched before an ordinary
widget keyPressEvent, so leaving it enabled in the Note region too would
have made the global shortcut fire INSTEAD of TimelineListWidget's own
Enter handling, silently breaking the digit-then-Enter jump-to-bar
feature. Three new tests cover: the enable/disable split itself, Enter
actually starting and stopping Preview from every other region and the
status bar, and a regression guard that typing a bar number then Enter
in the Note region still jumps rather than starting a Preview.

Options > Language (UK/US) -> Terminology (UK/US): user decision,
reverting the first round's own rewording. Achieved without reopening
the Tempo Offset/Terminology mnemonic collision the first round had
fixed by renaming to "Language": instead, Tempo Offset's own mnemonic
moved from "&Tempo Offset..." (T) to "Tempo Of&fset..." (F), freeing "T"
back up for "&Terminology (UK/US)".

UK/US items lost their mnemonics entirely (now plain "UK"/"US", no "&"):
user decision, and an answer to the user's own question ("Are these
hints because object nav doesn't read this out?"). What NVDA was
announcing ("UK, alt+u" / "US, alt+s") is a menu item's Qt/Windows
"KeyboardShortcut" accessibility property - the SAME mechanism behind
every other mnemonic in this app, not something specific to object
navigation. It's real: Alt+U while this submenu is open really does
select UK. The user's point was that it's unwanted HERE specifically -
"I don't think we need global shortcuts for these. The user just
changes them with the menu" - a two-item mutually-exclusive submenu
reached by arrowing in doesn't need a quick-jump letter the way a
longer, less frequently opened menu might. Removing the "&" is the only
way to stop Qt from registering (and NVDA from announcing) that
accelerator at all - there's no way to keep a working Alt-letter without
it also becoming an announced "hint".

Reorder Attributes / Reorder Parts / Performance Report: user decision -
give all three a real global Ctrl+Shift+<letter> shortcut (matching the
established pattern for every other item that opens a dialog:
Instruments/I, Key Signature/K, Mixer/X, Preview Settings/V, Live MIDI
Input Settings/L, Voice Control Settings/R, Tuner/T) AND remove their
menu mnemonics entirely. These three were the odd ones out: they open a
dialog exactly like all the items above, but had never been given a real
shortcut - only an Alt-only mnemonic that only ever worked with the
Options/Tools menu already open, which is a fundamentally different,
much narrower thing than a real global shortcut, yet NVDA announced it
in exactly the same "alt+<letter>" phrasing, which read as false/
misleading. Assigned: Reorder Attributes = Ctrl+Shift+A, Reorder Parts =
Ctrl+Shift+O (not P - P is Toggle Position Announcer's own single-Ctrl

announce with no corresponding real capability behind it. Both items are
